# Guía de instalación — AV-008

Este paquete **no** es un repositorio completo. Se superpone sobre el AegisVault de AV-007 con `package-lock.json` ya versionado. **No borrar** `src/tooling/smoke.ts`, ni `scripts/verify-build.mjs`, ni `public/manifest.json`. No se modifican dependencias ni se reemplaza `package-lock.json`.

## 1. Antes de modificar archivos

```bash
cd ~/proyectos/AegisVault
git status -sb
git branch --show-current
git log -1 --oneline
```

No extraer sobre una rama con cambios sin revisar. AV-007 debe integrarse a `main` y aceptarse formalmente antes de cerrar AV-008; si el estado de AV-007 sigue «En revisión», resolverlo antes del cierre de esta fase.

## 2. Rama de trabajo

```bash
git switch main
git pull --ff-only origin main
git switch -c chore/AV-008-module-boundaries
```

Si la rama ya existe, usar `git switch chore/AV-008-module-boundaries` en lugar de crearla.

## 3. Extraer paquete

Descargar el ZIP e introducir su ruta real, por ejemplo:

```bash
unzip -l /ruta/AegisVault_AV-008.zip
unzip -o /ruta/AegisVault_AV-008.zip -d ~/proyectos/AegisVault
```

Sobrescribe **solo** `package.json` y `eslint.config.mjs`, además de crear los nuevos archivos. Revisar diff antes de aceptar; si has cambiado dependencias después de AV-007, no sobrescribir sin comparar.

## 4. Verificación

```bash
npm ci
npm run arch:check
npm run test:architecture
npm run format
npm run check
npm audit
git diff --check
git status -sb
```

**Puntos de control:**

- El verificador debe indicar que no hay infracciones de capas.
- La suite `node:test` debe pasar sus casos negativos (rechazar imports indebidos es un test exitoso).
- `dist/av007-smoke.js` sigue existiendo, `dist/manifest.json` no.
- El análisis no detecta scripts externos ni dependencia de servidor.

## 5. Documentar y registrar cambios

En `CHANGELOG.md`, bajo `## [Unreleased]` / `### Added`, anotar:

```text
- **AV-008:** estructura modular core/extension/ui/shared y verificador automatizado de dependencias, con pruebas negativas de importaciones ilegales.
```

En la tabla de `ROADMAP.md`, poner AV-008 «En revisión: pruebas de arquitectura pendientes de aceptación» solo después de verificarlas; no editar ni renumerar la ficha del punto. Si AV-007 todavía no está aceptado, tampoco marcarlo como completado por inferencia.

### Antes del commit

```bash
git add package.json eslint.config.mjs src/core src/extension src/ui src/shared \
  scripts/check-boundaries.mjs tests/architecture docs/architecture/AV-008-modules.md \
  docs/setup/AV-008.md CHANGELOG.md ROADMAP.md

```

Si todo está correcto y el punto fue aceptado:

```bash

```

No ejecutar merge/push hasta comprobar el resultado y dar conformidad. No guardar nunca secretos o respaldos reales dentro del repositorio.
